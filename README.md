# Лабораторная работа №1 — Redis / NoSQL

## Предметная область

Разрабатывается система уведомлений для **небольшого кинотеатра с одним кинозалом**. В системе администратор формирует расписание показов фильмов и категории, а авторизованные пользователи получают информацию о фильмах и общие уведомления о ближайших премьерах. Бронирование билетов в рамках работы не реализуется.

## PostgreSQL

PostgreSQL используется как основное постоянное хранилище данных:

- **User** — пользователи системы;
- **Role** — роли `ADMIN` и `USER`;
- **Category** — категории фильмов;
- **Movie** — фильмы и время их показа.

Связи между сущностями:

```text
User M:N Role
Category 1:M Movie
```

## Redis

Redis используется для хранения временных и часто запрашиваемых данных, а также для реализации механизмов конкурентного доступа.

### Кэширование категорий

Часто запрашиваемые категории хранятся в Redis в качестве кэша. При первом запросе категория загружается из PostgreSQL и сохраняется в Redis на 5 минут. При повторном запросе данные берутся из кэша без обращения к PostgreSQL.

```text
category:<id>
```

### Уведомления

Уведомления о ближайших премьерах хранятся в Redis с использованием **TTL**. Уведомление создаётся за 3 часа до начала фильма и автоматически удаляется после начала показа.

Ключ:

```text
notification:<id>
```

### Хранение блокировок

Redis используется для временного хранения блокировок расписания. При добавлении фильма устанавливается блокировка на конкретный день, чтобы несколько параллельных запросов не могли одновременно изменить расписание.

```text
lock:<date>
```

Блокировка создаётся с использованием NX и EX: 

NX позволяет установить её только если такой блокировки ещё нет, а EX задаёт время её автоматического удаления.
